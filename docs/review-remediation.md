## Maintainability recommendations

- **S1:** isolate the repaired hold translation and issued-receipt contract in small focused modules. Do not replace the existing lifecycle with a generic workflow framework or collapse independent holds.
- **S2:** separate CLI grammar (`cli_parser`) and the operator-control adapter (`cli_controls`) from orchestration. Parser declarations and adapter statements were AST-compared with the baseline; command syntax, exception boundaries and locking stay unchanged. Existing intake CLI tests exercise all four extracted control commands through autospecced production callees.
- **S3:** refresh current README/SERVICE verification/configuration guidance and affected contract docs. Historical acceptance notes are evidence for their original candidate, not current installation observations.

## Operational changes and remaining qualification boundaries

- Launcher configuration syntax is unchanged, but an ordinary unbounded artifact directory is no longer admitted. Provision a private dedicated tmpfs with byte **and** inode ceilings under the configured `scratch_mb`; its aggregate bound includes retained attempts. See the storage section in `factory_v1/README.md`. No mount or daemon configuration is installed by this source change. Volatile artifact storage requires deliberate durable evidence retention outside worker mounts.
- Runtime receipt issuance requires an independently reviewed host verifier and private scoped policy. This change supplies the verifier/consumer contract, not a fabricated attestation issuer or automatic spending renewal. Existing immutable authority files remain supported.
- An inherited next-iteration supervision fence is intentionally unsealed until the successor's own scoped service/readiness policy is selected. No unsupervised dispatch window, cross-iteration credentials, automatic installation or inherited grant is introduced.
- N/A deployment is explicit, pinned and still acceptance-checked; missing configuration and unknown/failing configured health remain blocked.
- Routine verification stays unit/focused-component only, with mocked external boundaries and the canonical no-external-execution guard. The 500-method ceiling, discovery, meaningful safety assertions and CI timeouts remain intact.
- No real worker/container/model, production deployment, service activation, native conversation or fault campaign is established by component results. User source-delivery authorization does not make those observations exist.
